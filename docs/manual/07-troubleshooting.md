# Troubleshooting

Start with the actual **Session state**, target path/architecture, stop reason, and the error displayed by the affected panel. A loaded target is not necessarily a live stopped process; a Python pause is not necessarily a native stop; an old visible row is not necessarily a fresh capture.

Use [the command reference](06-command-reference.md) for exact syntax rather than assuming a GDB, WinDbg, pwndbg, or LLDB alias behaves identically in mydbg.

## Build or startup fails

### Python and LLDB disagree

Run `lldb --print-script-interpreter-info` and configure with that compatible Python interpreter. The executable, headers, shared liblldb, and Python embedding files must agree. A successful unrelated system `python` import does not prove the embedded runtime is compatible.

Use a clean **system-dev** build directory when switching from bootstrapped to system analysis providers. Do not allow stale `.deps` paths or another LLDB installation's headers/library to satisfy a mixed configuration.

### LLDB prints a Python signal-handler traceback

With LLDB 21.1.8 and Python 3.14, otherwise successful headless runs have printed `ValueError: signal only works in main thread of the main interpreter` during LLDB's embedded-interpreter SIGINT setup. That diagnostic alone does not establish that the debugger job failed. Check the actual script exception, process state, and exit status; do not dismiss a genuinely failing run because it also contains this message. Keep the LLDB/Python components matched and include their versions when reporting the diagnostic.

### Missing Rizin/rz-ghidra symbols or decompiler setup

Rerun `./scripts/bootstrap-analysis-deps.sh` after pulling provider changes. The tracked patches include DWARF/type integration and the standalone SHA256 export used by sessions. An unpatched Rizin 0.8.2 with the right version string is not equivalent to the required patched build.

Confirm `core_ghidra.so`, matching headers/libraries, and its adjacent Sleigh specifications. Changing only one component can produce ABI errors or unsupported-language failures. The [build guide](01-getting-started.md) lists custom paths and requirements, including libpng for manual screenshots.

### SDL/OpenGL cannot start

The GUI requires a working display and OpenGL 3.3 context. A terminal-only server does not automatically supply either. Use `--headless-script` for automation that does not require a window. For real GUI captures/verification, use an off-screen display such as Xvfb and a working software OpenGL stack; SDL's non-graphical dummy backend is not a substitute for this OpenGL application.

### A library or screenshot disappeared after moving the binary

Keep analysis providers and their runtime search paths available. Keep the `manual/` directory beside the executable for PNGs; chapter text is embedded. The reader checks source assets first, then that adjacent directory. There is no general self-contained install bundle generated by the current build.

## Launch, attach, or connection problems

### Launch does not stop at main

Confirm main resolves in this build and inspect pending breakpoints. A stripped or unusual executable may need **Start at entry**. A program can exit before an expected symbol breakpoint. Do not infer success from the mere existence of a breakpoint ID.

Check launch arguments, working directory, environment, executable permissions, loader/interpreter, and required libraries. Saved arguments/cwd can affect later launches; inspect `argv`/LLDB settings or clear the session deliberately. Environment is not restored as durable session data.

### Attach is denied

Check user ownership, Linux ptrace policy, namespaces/containers, and whether another debugger already owns the process. Prefer launching a process you own. Do not reflexively disable system-wide security protections or attach to an unrelated important process.

Attach is not restart. Terminate kills the attached process; detach is a separate operation. Decide which you want before using a stop/close workflow.

### Remote connection never becomes usable

Verify the stub is running, its endpoint/profile matches, the local symbol ELF is the same build, and the target architecture is supported by both LLDB and the stub. QEMU user and system mode have different startup requirements. The profile does not start QEMU or configure its machine for you.

Do not expose a debug stub to an untrusted network. Use loopback or protected transport. Remote PID and address-space data must not be interpreted through the host's `/proc`.

If the stub lacks memory-region reporting, ELF-segment fallback cannot reconstruct all anonymous regions. A readable known address can coexist with an incomplete Memory map, value scan, heap view, or pointer-follow menu.

## Controls are disabled or keys do the wrong thing

- Stop the native target before memory/register edits, scans, and live code navigation.
- Check whether an automation job owns the control lease, including while its Python debugger is paused.
- Click the intended native or Python panel before using shared keys. F2 in the Python editor is not a native breakpoint toggle.
- Leave text fields/modals or complete keybinding capture. Input routing deliberately avoids interpreting typed letters as navigation/edit commands.
- Check Settings > Keybindings for cleared/conflicting assignments. Restore defaults resets all native, Python, and navigation bindings.

Code browsing while Python is paused is intentional, but does not release every native control. A script cancellation request is not a debuggee termination command.

## Code, types, or variable values look wrong

### Wrong address kind

Disassembly and memory generally use process load addresses. Decompiler function headers and durable annotations use ELF file virtual addresses. String results also expose file offsets. These are three different things; ASLR/load bias connects only the appropriate pair.

Use the selected module's load mapping. A plausible offset added to the wrong module base can still point to mapped but unrelated code. Changed shared-library bytes invalidate their old SHA256-keyed annotations.

### Missing or misleading DWARF

Keep matching embedded/separate/split debug information accessible. `.symtab` presence alone is not full source debug information. Optimized variables can be unavailable, out of scope, split, constant, or described by unsupported location operations. A declaration in an annotation does not guarantee a readable live object.

Ghidra output is reconstructed C-like analysis. It can normalize types/qualifiers and generate temporaries rather than reproduce original source. Rename/type edits do not change machine code or allocation layout. If an edit fails, inspect its error; failed edits are not persisted as successful overrides.

Memory dump's small typed-hint view is not a full ABI layout engine. Its inline struct display does not calculate arbitrary padding, alignment, bitfields, or C++ object layouts. Validate actual offsets before writing through a guessed type.

### Graph is partial or shows unknown edges

An unresolved indirect branch, unsupported flow instruction, external destination, or incomplete function analysis can produce a partial graph notice. That is an explicit analysis limit, not proof that the missing edge is impossible. Fit can make a large graph unreadable; zoom/pan or return to linear disassembly.

Run-until searches a bounded linear instruction list and runs to a selected address. It is not dynamic trace-until-condition and does not guarantee the address lies on the executed path.

## Memory, scans, and heap results are incomplete

- The GUI dump is at most 256 bytes and can be partial; choose another base or use a bounded read command/API for more.
- Pointer navigation needs enough bytes, known target width/order, and a suitable destination mapping. A clipboard export setting does not change target pointer interpretation.
- Binary strings come from the local ELF, not process RAM. The UTF-16 option recognizes only the supported ASCII/TAB subset, not all Unicode.
- Value scans use naturally aligned typed addresses in captured mappings. Unaligned values need a byte search. Unknown-initial scans can exceed the candidate preflight bound; that is a rejection, not a valid empty scan.
- Only the first 10,000 value candidates are displayed, but all retained candidates refine. Current/Previous are scan snapshots, not live watches.
- Restart/new generation clears scans and patch ledgers. Memory patches are not replayed from disk sessions.
- Heap analysis requires a plausible glibc-style `[heap]` mapping and is bounded. Different allocators, remote maps, arenas, mmap chunks, corruption, and unsupported layouts can make it incomplete.
- The bin-named helpers classify captured free-looking chunks by size; they do not prove actual allocator-bin membership. try_free never invokes free.

A failed raw write/revert is not guaranteed to leave every byte untouched. Check the returned error and re-read the affected memory. Keep a recoverable target and restart when a mutation makes its state uncertain.

## Saved-session problems

### Changes are not retained

Inspect **Session > Saved session** for identity, counts, and errors. A valid local executable/module image is required. The directory must be usable under MYDBG_SESSION_DIR, XDG_STATE_HOME, or HOME. An empty/invalid explicitly configured location is not an intentional "disable persistence" switch.

A new SHA256 means a new session even when the path/build ID is unchanged. Some state is intentionally excluded: live memory/registers, one-shot/internal breakpoints, hardware watchpoints, command callbacks/scripted resolvers, execute watches, environment, and unsafe runtime-only addresses.

Arbitrary LLDB scripts are reconciled only after they return. They can create and run a target before automatic restoration has an opportunity to apply. Prefer explicit load/launch API operations for predictable ordering.

### Corrupt, incompatible, or unsafe file

The store reports malformed/unsupported/unsafe data rather than silently overwriting it. Back up private session files if you need forensic recovery. If you intend to discard that state, stop the process/end the Python lease and click **Clear saved session**. Clearing explicitly replaces invalid saved state and prevents queued old edits from repopulating it.

Do not hand-copy raw address records between unrelated hashes and expect relocation safety. Session files can contain sensitive paths, arguments, comments, types, and expressions; treat them as private debugging data.

### Clearing did not reset the theme/layout

That is intentional. SHA256 session state and the executable-adjacent mydbg.ini are separate. Clear saved session removes supported authored analysis/debugger state, not global preferences. To reset the latter, close the application and back up/move its adjacent mydbg.ini, then restart.

## Python workflow problems

- A disk job needs a callable run(dbg). It is not executed as `__main__`, and Debugger is injected rather than constructed by an external client.
- --script runs immediately. Use editor Load to inspect first.
- Run/Debug use the current buffer; py run and command-line forms use disk contents.
- A returned snapshot is a copy. wait_for_stop can return the current stop immediately; use continue_and_wait when you require a later stop.
- Process recv returns at most the requested size; recvuntil may return EOF without its delimiter. Check protocol markers and tolerate terminal echo/CRLF appropriately.
- Initial output may precede Process-handle creation; inspect snapshot.output for retained earlier bytes.
- Do not reuse a Process after load/restart. Receive generation checks do not make stale send handles safe.
- API timeout/cancellation does not retract an already queued command or kill the process.
- Stop is cooperative. An untraced file job's pure-Python loop or a blocking extension may prevent prompt cancellation/shutdown. Run untrusted/unbounded automation in an external isolation boundary.
- No Python event/plugin/decompiler API or evaluation REPL is supplied. Native plugin loading also does not happen in --headless-script.

See [the complete API contract](08-python-automation.md) before treating a missing method or different exception type as a runtime installation error.

Those are specific observed test boundaries, not permission to suppress unrelated errors or a claim that every operation on those architectures is broken. Report the target architecture, local/remote mode, stub/version, exact command, and complete error when encountering a different failure.

## Reporting a reproducible problem

Include:

- The mydbg revision/build preset and compatible LLDB/Python/provider versions.
- Target architecture, width, endianness, and local/remote/QEMU profile.
- Whether debug information and local module images are available/matching.
- Initial state, selected thread/frame, exact commands or a minimal run(dbg) script, and expected/observed stop reason.
- The affected error/traceback and whether a fresh isolated session directory changes the behavior.

Do not send secret target data, private session files, credentials in launch arguments, or entire memory dumps without reviewing them. A minimal owned fixture and a headless script are usually safer and more reproducible than a screenshot alone.
